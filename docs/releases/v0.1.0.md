## The page

- Browser-only X12 835 remittance explainer. No server, no build step, no install — open `index.html` from disk or from GitHub Pages and both behave identically.
- Content Security Policy with `connect-src 'none'`, so the browser itself blocks every network request. No CDNs, no fonts, no analytics, nothing written to localStorage or cookies.
- Reads the delimiters the `ISA` declares, splits the file into payment and claim records, and steps through them with Prev/Next, a dropdown or the arrow keys.
- A count per record kind above the navigator, each a button that filters to it, and a filter box matching any term in the label or the raw segments.
- Handles files with no `ISA`/`GS` envelope at all — a bare `ST`…`SE` transaction set is what plenty of integrations hand you.

## Coverage

- Payment: `BPR`, `TRN`, `REF`, `DTM`, `N1`/`N3`/`N4`/`PER` for payer and payee, `LX`, `TS3`, `TS2`.
- Claim: `CLP`, `CAS`, `NM1`, `REF`, `DTM`, `AMT`, `QTY`, `MIA`, `MOA`.
- Service lines: `SVC`, `CAS`, `DTM`, `AMT`, `REF`, `LQ`.
- Provider-level money: `PLB`, all six adjustment pairs — overpayment recovery, interest, capitation, forwarding balances.
- Envelope: `ISA`, `GS`, `ST`, `SE`, `GE`, `IEA`, with an `SE01` segment-count check.

## It checks the arithmetic

- Claim: charged = paid + every adjustment on the claim.
- Service line: line charge = line paid + the adjustments that follow it.
- Payment: `BPR02` = claims paid minus the provider-level adjustments in `PLB`.
- Anything that does not balance is flagged where you see it, not buried.

## Payer profiles

- Differences between payers go in a profile — a partial dictionary layered on the base one — rather than in rendering code. Anything a profile explains is tagged on the page with the profile's name.
- Commit a profile to a fork, or load one as JSON at runtime so a confidential companion guide never leaves the tab.
- **Download profile stub** builds a JSON skeleton of every segment, element position and code the page could not explain, with no field contents in it.

## Conformance corpus

- `conformance/` holds 18 remittances from four unrelated open-source projects, all MIT or ISC: denials, reversals, capitation, forwarding balances, secondary payers, and a payer that omits an element and shifts everything after it.
- Every file carries an `.info` sidecar naming its upstream repository, commit, path, permalink, SHA-256, licence, copyright holder and required attribution, all verified byte-for-byte against the upstream blob.
- `tests/conformance.test.js` parses the corpus on every run and refuses to let the unexplained counts grow; `tests/provenance.test.js` refuses a file with no recorded source or an unredistributable licence.
- Nothing here is copied from an X12 Technical Report Type 3.

## Licensing

- Apache-2.0. Segment IDs, element positions and element names are identifiers; every explanation is written in our own words.
- CARC, RARC and NUBC code descriptions are never bundled — codes are shown and marked as external code lists, and a profile supplies the descriptions.
